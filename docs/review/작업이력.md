## 3-3 · X-1. 학습·평가 데이터셋 — 해외 공개셋으로 전환

AI Hub 정신건강 데이터는 **안심존 전용 + IRB 심의 결과 통지서 필수**로 6주 일정 내 접근이 불가능함을 확인했습니다. 문서 전반의 "AI Hub 2종" 인용을 해외 공개 데이터셋으로 교체합니다.

### 라이프로그 모델 (LSTM AE + LightGBM)

| 데이터셋 | 출처 | 규모 | 신호 | 라벨 | 접근 |
|---|---|---|---|---|---|
| **LifeSnaps** ★주 | EU / Zenodo | 71명 · 4개월 · 7,100만 행 · 35종 | Fitbit Sense — 수면단계 · 심박 · 활동 · 스트레스 | PANAS(정서) · STAI(불안) · 자가보고 mood | [Zenodo 공개](https://zenodo.org/records/8084982) |
| **Depresjon** ★보조 | Norway · SimulaMet | 55명 (우울 23 / 대조 32) · 분 단위 | actigraphy 활동량 | **MADRS 우울 임상 척도** | 공개 |
| PMData | Norway · SimulaMet | 16명 · 5개월 | Fitbit 분 단위 심박 · 활동 · 수면 | 자가보고 라이프로그 | 공개 |
| WESAD | Germany | 15명 | 흉부+손목 EDA · ECG · 가속도 | baseline / stress / amusement | 공개 |

**채택: LifeSnaps(주) + Depresjon(보조).**

- **LifeSnaps** 가 LISN 의 수집 항목(활동량·수면단계·심박·HRV)과 가장 정합적입니다. Fitbit Sense 기반이라 신호 구성이 거의 일치하고, PANAS·STAI 자가보고가 붙어 있어 **감정 9종 · risk_score 매핑에 직접 쓸 수 있습니다.** 4개월 연속 데이터라 **LSTM Autoencoder 의 정상 패턴 학습**에 필요한 장기 시계열도 확보됩니다.
- **Depresjon** 은 신호가 활동량 단독이라 약하지만 **MADRS 라는 임상 척도 라벨**을 가집니다. LightGBM 2차 위험도 분류의 라벨 근거로 씁니다.

> **⚠ WESAD 는 재검토가 필요합니다.** 현재 01 기획서·발표자료 slide12 에 들어 있지만, **실험실 환경에서 유도한 급성 스트레스** 데이터라 일상 라이프로그와 도메인이 다릅니다. 15명 규모도 작습니다. 유지하려면 "급성 스트레스 반응 참조용"으로 역할을 한정해 서술하는 편이 안전합니다.

### 위기 대화 탐지 평가셋

**해외 코퍼스를 번역해서 평가셋으로 쓰는 것은 권장하지 않습니다.** 서비스가 한국어 챗봇이므로 (1) 번역체가 실제 한국어 발화와 다르고 (2) 번역 품질이 평가 지표에 섞여 들어갑니다.

**대신 라벨링 기준만 차용합니다.**

- **CLPsych 2019 Shared Task** 의 위험도 4단계 — `no / low / moderate / severe risk` 체계를 자체 평가셋의 라벨링 기준으로 채택합니다. [ACL Anthology](https://aclanthology.org/W19-3003/)
- 효과: **"라벨 체계를 팀이 임의로 정한 게 아니라 국제 공유 태스크 기준을 따랐다"** 는 방어 논리가 생깁니다. 평가셋이 전량 자체 작성이 된 상황에서 `02-B` 의 자가검증 취약점을 상당 부분 보완합니다.
- 참고: [UMD Reddit Suicidality Dataset](https://psresnik.github.io/umd_reddit_suicidality_dataset.html) (SuicideWatch 11,129명 + 대조군 11,129명, CLPsych 2019 학습·평가 데이터 포함)은 **DUA 서명 등 기관 절차가 필요**해 6주 일정에는 넣기 어렵습니다. 라벨 기준 참조용으로만 인용하세요.

**따라서 평가셋 200건은 전량 팀 자체 작성이며, `02-B` 의 "프롬프트 설계자와 분리된 인원이 작성" 요건은 선택이 아니라 필수입니다.**

## 3-5. 긴급 상담 UI (MLCM_510) — 신규 발견

3-1 확인 과정에서 발견한 사항입니다. 원 안건·체크리스트 어디에도 없었습니다.

### (1) 개인정보 제3자 제공 동의 체크박스 — 삭제 확정

02 요구사항정의서 MLCM_510 이벤트 흐름 3단계의 동의 체크박스 요건을 삭제합니다. 문제 3가지:

1. **위기 순간의 마찰** — 정신건강 앱 위기 지원 연구의 공통 원칙은 "속도와 극단적 단순함"입니다. 우울 삽화·공황 상태에서는 인지 자원이 극도로 제한되므로 위기 버튼은 누른 즉시 사전 설정 시퀀스가 실행되어야 합니다.
2. **구현 불가능한 약속** — 앱이 109 에 위험도 데이터를 전달할 API 나 기관 협약이 없습니다. 실제 동작은 `tel:` 발신뿐입니다. **`02-A` 의 "지킬 수 없는 보장"과 같은 유형의 결함.**
3. **[확인] 동의 요건** — 개인정보보호법상 제3자 제공 동의는 제공받는 자·목적·항목·보유기간을 특정해야 하는데 "해당 기관에 제공될 수 있습니다"는 불특정.

### (2) CRITICAL 단계 = `109` 단일 노출

109 는 단순 상담이 아니라 **구조 연계 채널**입니다(상담원이 위기 판단 시 통화 유지한 채 경찰 출동 요청). 1577-0199 는 지역 센터로 연결되는 일반 정신건강 상담이며 야간·공휴일엔 광역센터로 넘어갑니다. 위기 순간에 성격이 다른 선택지 2개는 인지 부하만 늘립니다.

- CRITICAL → `109` 단일 · CAUTION → `1577-0199` 보조 안내(선택)

### (3) 표현 기준 · 구현 시 검증

- [자살예방 보도준칙 4.0](https://www.mohw.go.kr/board.es?mid=a10503010100&bid=0027&act=view&list_no=1483567)(2025 개정) — **"극단적 선택" 대신 "사망"**. 적용 범위에 SNS·온라인 커뮤니티 등 개인 매체 포함.
- 연구에 따르면 누적 350만 다운로드 규모의 14개 정신건강 앱이 **틀렸거나 연결되지 않는 위기 번호**를 넣고 있었습니다. 번호는 실제 발신 테스트로 검증하고 오프라인에서도 버튼이 동작해야 합니다. ([Psychiatric Services](https://psychiatryonline.org/doi/10.1176/appi.ps.20240485))

## 4-3. 팀 공용 DB — 캠퍼스 공용 PostgreSQL 확보

각자 로컬 DB 를 쓰면 5주차 통합 테스트 시점에 스키마 불일치가 터지는 문제가 있었습니다.
**학교에서 제공하는 공용 PostgreSQL 인스턴스를 받아 이 문제가 해소되었습니다.**
Neon·Supabase 등 외부 클라우드는 검토 대상에서 제외합니다.

> **🔑 접속 정보는 저장소에 두지 않습니다.**
> 이 저장소는 **공개(public)** 라 커밋하는 순간 노출되고, 삭제해도 커밋 히스토리에 남습니다.
> 접속 정보는 **단톡방 고정 공지**와 **Notion 프로젝트 페이지**에만 둡니다.

**운영 규칙**

- **`db/schema.sql` 은 PM(이응균)이 1회만 실행합니다.** 공용 DB 라 각자 실행하면 `CREATE TABLE` 이 충돌합니다. 현재 스크립트에 `IF NOT EXISTS` 가 없습니다.
- 애플리케이션 코드에 접속 정보를 직접 쓰지 않고 **`.env` 로 분리**합니다. `.gitignore` 에 이미 포함되어 있습니다.
- **포트가 기본값(5432)이 아닙니다.** DBeaver·psql 접속 시 공지의 포트로 바꿔야 합니다. 접속 실패 문의의 대부분이 여기서 발생합니다.

> **⚠ 스키마 실행 전 확인** — `db/schema.sql` 이 `gen_random_uuid()` 를 쓰는데 이는 PostgreSQL 13 이상에서만 내장 함수입니다. 캠퍼스 서버 버전이 낮으면 `CREATE EXTENSION IF NOT EXISTS pgcrypto;` 를 먼저 실행해야 합니다. 접속 후 `SELECT version();` 으로 확인하세요.

## 선행 확정 안건

- **안건 2** — iOS / Apple Health 구현 제외. 단 `platform_type` enum 의 `APPLE_HEALTH` 값은 유지(제거하면 컬럼에 값이 하나뿐이라 존재 이유가 사라짐). 근거는 "Health Connect 가 Android 전용 API"라는 기술적 제약.
- **안건 3** — 위기 탐지는 KcBERT 파인튜닝이 아니라 **키워드 규칙 + OpenAI 프롬프트 2단계**. 1차 키워드 필터는 백엔드 내부에 두어 API 장애 시에도 단독 동작.
- **안건 4** — 전 컬럼 AES-256 이 아니라 **위험도 기반 계층적 보호**. 라이프로그 측정치는 기간별 집계·복합 인덱스가 서비스 핵심 동작이라 컬럼 암호화 대상에서 제외.

## 원 개정안에서 수정해 반영한 것 3건

1. 매체 암호화를 **조건부화** — PostgreSQL 은 자체 TDE 가 없어 OS/클라우드 레벨로만 가능. 실제로 켜지 않으면 미이행 보장이 됨
2. "단독으로는 개인을 특정할 수 없는 구조" 주장 **완화** — USERS 와 측정치가 단일 DB 안에 물리적 FK 로 연결되어 `JOIN` 한 번이면 실명과 붙음. 접근통제를 주 통제수단으로 재배치
3. **평가셋 작성자 분리 요건 추가** — 프롬프트 설계자가 평가셋도 만들면 Recall 90% 가 자동으로 나옴
