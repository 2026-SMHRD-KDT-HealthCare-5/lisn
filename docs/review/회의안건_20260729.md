## 🔴 1. 안건 1-1 — Health Connect 데이터 수집 구조 (최우선)

**왜 최우선인가**
이 하나가 `02-H` · `04-B` · `05-A` 세 개 항목을 잠그고 있습니다. 이게 안 정해지면 요구사항정의서·DB요구사항분석서·테이블명세서를 손댈 수 없습니다.

**쟁점**
02 요구사항정의서 MLCM_200 의 이벤트 흐름이 **서버 pull 구조**로 쓰여 있습니다.

> 백엔드 스케줄러가 트리거 → DB에서 스마트워치 연동 토큰이 유효한 사용자 목록을 조회 → 대상 사용자별로 OS 헬스 플랫폼 API에 데이터를 요청

그런데 Health Connect 는 Android **on-device 권한 모델**이라 서버가 보유할 OAuth 토큰이 없고, 서버가 사용자 기기의 데이터를 직접 당겨올 수 없습니다. 앱이 push 하는 구조여야 성립합니다.

**결정해야 할 것**
- [ ] 앱 push 구조로 전환 확정 여부
- [ ] 전환 시 15분 주기 스케줄러의 주체 — 백엔드 → **앱 클라이언트 백그라운드 워커**
- [ ] NFR-DV-002 의 재시도(3회 / 30초 간격) 주체도 함께 앱으로 이동하는지
- [ ] 앱이 꺼져 있거나 백그라운드 제한에 걸린 경우 미수신 처리 방식
