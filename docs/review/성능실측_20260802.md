## ✅ `NFR-TS-001` — 위기 발화 158ms

```
「요즘 정말 죽고 싶다는 생각이 들어요」
  → 판정 EMERGENCY · 중앙값 158ms · 최댓값 187ms   (예산 3000ms)
```

**LLM 을 기다리지 않기 때문에 빠릅니다.** HIGH 키워드가 걸리면 문맥 판단 없이
CRITICAL 로 확정하고 즉시 끊습니다(`chat.py:61`). 안전 요건을 외부 API 지연에
묶어두지 않은 설계가 그대로 수치로 나왔습니다.

> ⚠ **시험 발화를 고를 때 사전을 먼저 보세요.** 처음에 쓴
> 「다 그만두고 싶어요」는 **키워드 사전에 없어** CHAT 으로 나왔습니다.
> 시스템 실패가 아니라 제 시험 설계 오류였습니다.
>
> 다만 사전에 「다 끝내고 싶」·「다 내려놓고 싶」은 있는데 「그만두고 싶」이
> 없는 것은 **메울 만한 빈틈**입니다.

## ⚠ `NFR-DV-001` — 측정하지 못했습니다

측정값이 3.6초·8.0초로 나왔지만 **무효입니다.** 재는 도중 Gemini 무료 한도를
소진해, 실제로는 LLM 이 실패하고 429 왕복 시간을 잰 것이었습니다.

```
429 RESOURCE_EXHAUSTED
  quotaId   GenerateRequestsPerDayPerProjectPerModel-FreeTier
  quotaValue 20          ← 모델당 하루 20건
```

확인 방법 — 응답 시간만 보면 정상처럼 보입니다.

```
경과 3588ms
reply   : None ⚠ (LLM 실패)
verdict : 받음
```

**`analyze_and_reply` 는 실패를 삼키고 (None, verdict) 를 돌려주므로**
호출이 성공한 것처럼 보입니다. 시간만 재면 못 알아챕니다.

> 기존 기록은 **2.19초**입니다([`USAGE_LOG.md`](../llm/USAGE_LOG.md) LLM-004).
> 그 값을 뒤집을 근거는 없습니다. 다시 재려면 **한도가 초기화된 뒤** 첫
> 시도로 재야 합니다.

### ⚠⚠ 이게 시연 위험입니다

**모델당 하루 20건**입니다. 분당이 아니라 **하루**입니다.

- 대화 한 번에 `reply` + `crisis` **두 모델**을 씁니다
- 즉 **대화 20번이면 그날 한도가 끝납니다**
- 끝나면 사용자는 폴백 문구만 받습니다 — 화면은 멀쩡해 보입니다

발표 리허설을 몇 번 돌리면 **본 발표 때 LLM 이 죽어 있을 수 있습니다.**
`LLM_PROVIDER=openai` 전환이 막혀 있는 것이 여기서 실제 위험이 됩니다.

## ⚠ AI 서버가 `.env` 를 읽지 않습니다

```
POST /internal/analyze/lifelog → 503
{"detail":"DB 연결 실패: connection was closed in the middle of operation"}
```

asyncpg 가 원인을 감춥니다. PostgreSQL 로그에 실제 원인이 있었습니다.

```
치명적오류: 사용자 "postgres"의 password 인증을 실패했습니다
```

`ai/server/main.py:32` 는 `os.getenv` 만 씁니다. **`.env` 를 로드하지 않아**
환경변수를 손으로 넣지 않으면 하드코딩 기본값
(`postgresql://postgres:postgres@localhost:5432/lisn`)으로 붙습니다.

`CLAUDE.md` 는 「`AI_DATABASE_URL` 이 없으면 `DATABASE_URL` 을 씁니다」라고만
적어 두었고, **그 값을 어떻게 넣는지**가 빠져 있습니다. 문서대로
`cd ai\server; uvicorn main:app` 하면 DB 를 못 붙습니다.

> 응답 시간 60ms 는 **인증 실패까지 걸린 시간**이지 분석 시간이 아닙니다.
