# 힐링 콘텐츠 큐레이션 기준

> **작성일** 2026.07.31 · 대상 `HEALING_CONTENTS` · 근거 04 문서 7항 · `FR-CS-001` · `MLCM_400`
>
> 시드 파일은 [`db/seed_healing_contents.sql`](../../db/seed_healing_contents.sql).

---

## 왜 사람이 골라야 하는가

04 문서 7항이 등록 조건을 이렇게 못 박았습니다.

> 자극적이거나 특정 감정에만 극단적으로 특화된 콘텐츠는 배제하고, 중립적이고 보편적으로 안정감을 주는 콘텐츠만 사전 검수 후 등록

**이 원칙의 목적은 추천 정확도가 아니라 안전입니다.**

AI 의 감정 분류는 틀릴 수 있습니다. 그래서 "정확히 맞히면 안전하다" 는 설계를 쓰지 않고, **콘텐츠 풀 자체를 안전하게 만들어 분류가 빗나가도 해가 없게** 했습니다. `FR-CS-001` 이 같은 말을 합니다.

> 추천 정확도가 낮은 경우에도 안전성을 보장함

URL 을 검수 없이 채우면 이 설계가 그대로 무너집니다. 자동 생성이나 대량 수집으로 채울 수 없는 이유입니다.

## 필요한 분량

| 항목 | 값 |
|---|---|
| 대상 감정 | **6종** — `SADNESS` `ANXIETY` `LONELINESS` `ANGER` + `JOY` `DELIGHT` `HAPPINESS` 중 일부 |
| 카테고리 | `MUSIC` `FOOD` `EXERCISE` `ARTICLE` |
| 감정당 최소 | 3~5건 |
| 전체 목표 | **20~30건** |

`DESPAIR` · `CRISIS` 는 **등록하지 않습니다.** `CRITICAL` 판정이면 `MLCM_510` 2단계에 따라 콘텐츠 추천이 즉시 중단되고 긴급 상담 연결로 전환됩니다. 서버도 `action != CONTENT` 면 아예 조회하지 않습니다.

> 실질적으로 필요한 건 `CAUTION` 감정 4종(`SADNESS`·`ANXIETY`·`LONELINESS`·`ANGER`)입니다. `NORMAL` 감정은 추천이 트리거되지 않지만, 화면 테스트를 위해 몇 건 넣어두면 편합니다.

각 후보에 대해 전부 **예** 여야 등록합니다.

### 안전

- [ ] 자해·자살·약물·음주를 다루거나 암시하지 않는가
- [ ] 우울·불안을 **미화하거나 낭만화**하지 않는가
- [ ] 특정 종교·정치·상업적 권유가 없는가
- [ ] 의학적 조언이나 진단으로 읽힐 표현이 없는가 (`FR-AI-002` 진단 금지와 같은 선)

### 톤

- [ ] 자극적이지 않은가 (큰 소리, 빠른 편집, 강한 색)
- [ ] "힘내세요" 식의 **강요형 위로**가 아닌가
- [ ] 사용자를 환자로 취급하지 않는가

## 카테고리별 방향

| 카테고리 | 맞는 것 | 피할 것 |
|---|---|---|
| `MUSIC` | 가사 없는 연주, 자연음, 명상 가이드 | 가사가 감정을 특정하는 곡, 격한 곡 |
| `FOOD` | 간단한 따뜻한 음식, 차 | 폭식·다이어트를 다루는 것 |
| `EXERCISE` | 스트레칭, 호흡법, 가벼운 산책 | 고강도 운동, 체형 관리 |
| `ARTICLE` | 짧은 글귀, 감정에 대한 담백한 설명 | 자기계발식 훈계, 투병기 |

**감정별로 다르게 고르려 애쓰지 마세요.** 04 문서가 "특정 감정에만 극단적으로 특화된 콘텐츠 배제" 를 요구합니다. 같은 콘텐츠를 여러 감정에 매핑해도 됩니다.

## 등록 방법

`db/seed_healing_contents.sql` 의 예시 블록을 복사해 채웁니다. `emotion_id` 를 직접 쓰지 말고 `emotion_code` 로 조회하세요 — UUID 는 `gen_random_uuid()` 로 만들어져 환경마다 다릅니다.

```sql
INSERT INTO healing_contents (emotion_id, category, title, description, external_url)
SELECT emotion_id, 'MUSIC', '제목', '설명', 'https://...'
  FROM emotions WHERE emotion_code = 'ANXIETY';
```

등록 후 확인:

```sql
SELECT e.emotion_code, e.category, COUNT(h.content_id)
  FROM emotions e LEFT JOIN healing_contents h ON h.emotion_id = e.emotion_id
 GROUP BY e.emotion_code, e.category ORDER BY e.category, e.emotion_code;
```

`CAUTION` 감정 4종이 전부 0 보다 크면 홈 화면 추천이 동작합니다.

## 발표 대비

심사에서 **"콘텐츠는 어떻게 고르셨나요"** 가 나올 수 있습니다. 답할 거리를 만들어두세요.

- 선정 기준이 문서화돼 있다 (이 파일)
- **AI 분류가 틀려도 안전하도록** 콘텐츠 풀 자체를 제한했다
- `CRITICAL` 단계에는 콘텐츠를 매핑하지 않고 상담 연결로 전환한다

이 세 가지면 "추천 정확도가 낮으면 어떡하냐" 는 질문까지 함께 막힙니다.
