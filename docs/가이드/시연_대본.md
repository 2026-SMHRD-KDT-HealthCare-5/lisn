> 2026.08.22 작성. 최종 발표 **2026.08.28**.
> 발표 10분 = **시연영상 3분** + 발언 7분. **시연회 5분**은 별도·라이브입니다.

## 0. 두 시연은 목적이 다릅니다

|  | 시연영상 (3분) | 시연회 (5분) |
|---|---|---|
| 성격 | **녹화** — 다시 찍으면 됩니다 | **라이브** — 한 번뿐입니다 |
| 대기시간 | 편집으로 잘라냅니다 | 그대로 흐릅니다 |
| 관객 개입 | 없음 | 질문·요청이 들어옵니다 |
| 실패 비용 | 0 | 큼 |

**가르는 기준은 하나입니다 — 「지금 다시 만들 수 있는 상태인가」.**

- 다시 못 만드는 것 → **영상**. 선제 접촉은 *연속 이탈 3일*·*쿨다운 3일*·
  *09~21시* 세 조건이 동시에 맞아야 발생합니다. 무대에서 만들 수 없습니다.
- 아무 때나 눌러도 되는 것 → **시연회**. 관제 웹·리포트·일반 대화는
  언제 눌러도 같은 결과가 나옵니다. 관객이 검색어나 대화 내용을 정해도
  됩니다 — 그게 라이브의 값어치입니다.

> ⚠ **위기 발화 장면을 라이브로 하지 마세요.** 다시 찍을 수 없는 자리에서
> 「죽고 싶다」를 타이핑하는 것은 위험합니다. LLM 왕복이 늦어 정적이
> 생기고, 그 정적이 하필 그 문장 위에 얹힙니다. 영상에 넣으세요.

### 1-2. 데모 데이터를 **오늘로** 맞추기

로컬 DB 로 시연한다면:

```powershell
psql -U postgres -d lisn -f db/refresh_demo_dates.sql
```

**캠퍼스 공용 DB**(`backend/.env` 기본값)로 시연한다면 접속 문자열을 직접
넘기세요 — 아이디·비밀번호는 단톡방 고정 공지 참고:

```powershell
$env:PGCLIENTENCODING = "UTF8"
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" "postgresql://<아이디>:<비밀번호>@project-db-campus.smhrd.com:3310/<DB명>" -f "db\refresh_demo_dates.sql"
```

⚠ **`$env:PGCLIENTENCODING = "UTF8"` 를 빼먹지 마세요.** 한글 Windows
PowerShell 은 psql 클라이언트 인코딩이 `UHC` 로 잡혀 있어서, 이 파일 안의
`⚠` 같은 특수문자를 못 옮기고 `character ... has no equivalent in
encoding "UTF8"` 로 죽습니다(2026.08.25 실측). 트랜잭션 전체가
`ROLLBACK` 되니 DB 는 안 다치지만, 그 상태로는 데이터가 하나도 안 밀립니다.

⚠ **자정을 넘겼으면 반드시 돌리세요.** 시드는 상대 날짜로 들어가 있어서,
하루만 지나도 가장 최근 기록이 「어제」가 됩니다. 그러면 홈의 수면·활동량이
전부 「-」로 나옵니다. **화면이 깨진 게 아니라 오늘 데이터가 없는 것**인데,
촬영 직전에 이걸 만나면 원인 찾느라 시간을 다 씁니다.

⚠ **돌린 뒤 앱을 완전히 재시작하세요.** 파일 맨 아래 주석은 "당겨서
새로고침하거나 탭을 다시 누르라"고 되어 있는데, **둘 다 실제로는 화면을
안 바꿨습니다**(2026.08.25 실측 — 홈 탭을 재선택해도, pull-to-refresh
제스처를 줘도 「-」 그대로였고, 앱을 완전히 종료했다가 다시 띄우니
그제야 반영됐습니다). 에뮬레이터/실기기에서 앱을 스와이프로 완전히
종료한 뒤 다시 여세요.

⚠ **시드를 다시 돌리지 마세요**(`seed_demo_*.sql`). `DELETE FROM USERS` 로
시작해서 **FCM 토큰·선제 접촉 세션·앱 로그인이 전부 날아갑니다.**
날짜만 밀면 되는 일에 그걸 쓰면 복구에 30분이 듭니다.

### 1-5. 촬영 직전 점검 — **이 넷을 눈으로 확인하고 시작하세요**

| 확인할 것 | 정상 | 아니면 |
|---|---|---|
| 홈에 「마음이가 먼저 말을 걸었어요」 카드 | 있음 | → 2-1 참조 |
| 홈의 수면 시간·활동량 | 숫자 | → 1-2 다시 |
| 관제 대시보드 「전체 10명 중 9명 평가 완료」 | 3·3·3 | → 1-2 다시 |
| 상태표시줄에 남은 시스템 알림 | 없음 | → 아래로 지우기 |

⚠ **에뮬레이터 날짜가 PC 와 달라 보일 수 있습니다.** 실제로 PC 가
8/22 인데 상태표시줄이 **8/21** 이었습니다. 상단 바가 모든 컷에 찍히므로
촬영 전에 맞추세요.

원인은 시계가 아니라 **타임존**입니다. AVD 기본이 `GMT` 라 한국 시각
새벽에는 **전날로 보입니다**(06:13 KST = 전날 21:13 GMT). 시각 자체는
맞습니다.

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" shell "service call alarm 3 s16 Asia/Seoul"
```

⚠ `setprop persist.sys.timezone` 은 **Play Store 이미지에서 실패합니다**
(루팅이 안 됩니다). 위의 `service call alarm` 을 쓰세요 — 이건 됩니다.
확인은 `adb shell date` 로 하고, 상태표시줄이 바뀌는지도 눈으로 보세요.

⚠ **「Set a screen lock」 같은 시스템 알림을 지우고 시작하세요.** 알림
그림자를 내리는 컷에서 같이 찍힙니다.


> ⚠ **이 도구가 무엇인지 정확히 알고 쓰세요.** DB 에 **이미 있는** 선제
> 접촉 건을 찾아 **운영과 같은 경로**(`services/push.py`)로 알림을 다시
> 보냅니다. 제목·본문·페이로드가 `outreach.py` 와 한 글자도 다르지
> 않습니다. 판정을 새로 하거나, 세션을 만들거나, 없는 접촉을 지어내지

## 3. 시연회 5분 대본 (라이브)

**총 300초.** 순서를 이렇게 잡은 이유: **안 깨지는 것부터** 입니다.
관제 웹은 LLM 을 안 타서 즉답합니다. 먼저 신뢰를 얻고 대화로 갑니다.

| 순서 | 내용 | 초 | 왜 라이브인가 |
|---|---|---|---|
| 1 | **관제 웹** — 분포 → 정렬 → 검색 → 대상자 상세 차트 | 90 | 즉답합니다. 관객이 검색어를 정해도 됩니다 |
| 2 | **앱 홈 → 리포트** — 기간 전환, 감정·라이프로그 결합 차트 | 60 | 네트워크만 타면 되므로 안정적입니다 |
| 3 | **실시간 대화** — 관객에게 문장을 받아 입력 | 100 | **각본 없이 답한다는 증명.** 여기가 라이브의 값어치입니다 |
| 4 | 여유 · 질문 | 50 | |

### 순서 3에서 지킬 것

- **관객 문장을 그대로 받으세요.** 미리 정한 문장을 쓰면 라이브로 할
  이유가 없습니다.
- **위기 표현이 들어오면 피하지 말고 그대로 보여주세요.** 긴급 화면으로
  넘어가는 것이 정상 동작입니다. 다만 **「방금 이건 실제 상담기관 번호로
  연결됩니다」**라고 먼저 말하고 **통화 버튼은 누르지 마세요.**
- 응답이 3초를 넘으면 **말로 채우세요** — 침묵이 제일 나쁩니다.
  「지금 공감 응답과 위기 판정을 동시에 돌리고 있습니다」가 사실이면서
  자연스러운 채움말입니다.

### 순서 3이 실패하면

LLM 이 죽거나 느리면 **바로 관제 웹으로 돌아가세요.** 미리 정해두면
당황이 안 보입니다. 「지금 외부 API 가 느리네요 — 이럴 때를 위해
키워드 필터가 단독으로 동작하도록 만들어 뒀습니다」로 넘기면
**약점이 설계 설명으로 바뀝니다.**

## 4. ⚠ 알고 있어야 할 것 — 물어보면 이렇게 답하세요

### 4-1. 「채팅에서 감지한 위기는 관리자 화면에 뜨나요?」

**뜹니다.** 위기 발화가 확인되면 판정을 `EMOTION_RISK_SCORES` 에 남기고,
관제의 「위기 사건 이력」에 바로 올라옵니다.

> ⚠ **2026.08.22 이전에는 뜨지 않았습니다.** 이 대본을 쓰다 발견해
> 그날 구현했습니다(구현_갭 갭 9). 옛 빌드로 시연하지 마세요.

**여기서 자랑할 것은 「뜬다」가 아니라 「구분해서 뜬다」입니다.**

목록의 **「모델」 칸**을 보여주세요.

| 값 | 뜻 |
|---|---|
| `chat-crisis-llm-v1` | 키워드 + LLM 문맥 판정 둘 다 거친 것 |
| `chat-crisis-kw-v1` | **외부 API 장애로 키워드만 보고 내린 것** |
| `rule-…` / `seed-…` | 라이프로그 기반 일일 판정 · 시연용 데이터 |

말할 문안:

> 「키워드만으로 내린 판정은 **정밀도가 0.500** 입니다. 「예전에 죽고
> 싶었는데 지금은 괜찮아요」 같은 문장이 여기 걸립니다. 그래서 같은
> 심각이라도 **근거를 나눠 적었습니다.** 관리자가 오탐에 매달리느라
> 진짜를 놓치지 않게 하려는 것입니다.
>
> 그렇다고 키워드 단독 건을 빼지는 않았습니다. 외부 API 가 죽었을 때가
> 시스템이 가장 약한 때인데, **그때 관제까지 조용해지면 안 되니까요.**」

**한 세션에 한 번만 남깁니다.** 위기 상태의 사람은 연달아 말하는데,
그때마다 행을 넣으면 목록 첫 페이지를 그 사람 혼자 채워 **다른 위험군이
화면에서 밀려납니다.** 발화 자체는 대화 기록에 전부 남습니다.

⚠ 물어보면: **점수 100 은 잰 값이 아닙니다.** 「확정된 위기는 최고
위험도」라는 정의입니다. 대화 위기에는 개인 기준선 같은 척도가 없어서,
중간값을 넣으면 측정한 것처럼 보입니다.

### 4-2. 「이 데이터는 진짜인가요?」

**아닙니다. 만들어낸 데이터입니다.** 화면에 그렇게 적혀 있습니다 —
위기 사건 이력의 「모델」 칸이 `seed-demo-v0` 입니다.

> 「실사용자 데이터가 없어서 시연용으로 넣은 값이고, 화면에
> `seed-demo-v0` 로 표시되게 해 뒀습니다. 실제 판정은 `rule-` 로
> 시작합니다. 어느 쪽인지 화면에서 구분됩니다.」

### 4-3. 「정확도가 어떻게 되나요?」

**재현율 0.946 · 정밀도 0.921 · F1 0.933** (평가셋 211건, 2026.08.12).

- ⚠ **`0.919` 와 `0.793` 을 쓰지 마세요.** 각각 AI 초안으로 잰 값,
  라벨 기준 반영 전 옛 값입니다.
- ⚠ **위험도 판정(`MLCM_210`)의 정확도가 아닙니다.** 그건 규칙 기반이고
  임계값도 임의값입니다. 성능 근거로 쓰면 방어할 수 없습니다.
  물어보면 「위기 판정 성능이고, 라이프로그 위험도 쪽은 규칙 기반이라
  아직 성능 수치를 말할 단계가 아닙니다」.

### 4-4. 「정서 점수 94점이면 좋은 거 아닌가요?」

**높을수록 나쁩니다.** 홈에 「마음이 많이 힘들어 보여요」와 「94 / 100」이
나란히 있어서 오해하기 쉽습니다. 먼저 말해서 넘기세요 —
「점수는 **힘든 정도**입니다」.

### 4-5. 「워치 연동은요?」 「배포는요?」

둘 다 **하지 않았고, 안 한 이유가 있습니다.** 각각
`docs/결정/` 의 기록을 보고 답하세요. 「못 했다」가 아니라
「범위에서 뺐다」입니다.

## 5. 문제가 생기면

| 증상 | 실제 원인 | 조치 |
|---|---|---|
| 홈의 수면·활동량이 「-」 | 자정을 넘겨 오늘 데이터가 없음 | `refresh_demo_dates.sql` |
| 선제 접촉 카드가 없음 | 이미 답장했거나 세션 종료 | `demo_notify.py --dry-run` 으로 상태 확인 |
| 알림이 안 옴 | FCM 토큰 없음 | 앱 실행 → 알림 권한 허용 |
| 앱이 「서버에 연결할 수 없습니다」 | 릴리스 빌드의 평문 HTTP 차단 | `network_security_config.xml` 에 IP 추가 |
| 관제가 「전체 2명」 | 코호트 시드 없음 | `seed_demo_cohort.sql` |
| 대화 응답이 13초 | 죽은 무료 모델 재시도 | `.env` 의 모델을 바꾸거나 OpenAI 로 전환 |

**촬영은 서버·데이터·기기 순으로 세팅하고, 1-5 의 넷을 눈으로 보고
시작하세요.** 순서를 지키면 위 표를 볼 일이 거의 없습니다.
