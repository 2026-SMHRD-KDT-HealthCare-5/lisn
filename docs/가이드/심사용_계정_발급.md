# 심사용 계정 발급

최종발표 피드백 3번(「클라우드 배포완료 된 팀들은 상태 확인 후 링크 및 테스트
계정 전달」)의 **테스트 계정** 절차입니다. 2026.09.04 작성.

---

## 확인한 사실 — 운영 DB 에 계정이 하나도 없습니다

`check-email` 은 인증이 없어 계정을 만들지 않고도 존재 여부를 볼 수 있습니다.

```bash
B=https://101.79.24.15.nip.io/api/v1/auth/check-email
for E in demo.crisis@lisn-test.example admin.new@lisn-test.example admin@lisn.dev; do
  curl -sS -G "$B" --data-urlencode "email=$E"; echo "  $E"
done
```

2026.09.04 기준 셋 다 `{"available":true}` — 하나도 없습니다.
시드는 **운영 DB 에 적용된 적이 없고**(시드 계정 로그인 시 401 실측),
`admin.new@` 는 교내 공용 DB 에만 있습니다.

## 왜 회원가입만으로는 부족한가

가입만 한 계정은 **화면이 비어 있습니다.**

| 화면 | 빈 계정일 때 |
|---|---|
| 앱 홈 | 수면 · 걸음 · HRV 가 전부 `-` |
| AI 판정 | 실측치 3일치 미만이면 **422** (`ai/server/main.py:191`) |
| 관제 웹 위기 사건 이력 | `risk_level='CRITICAL'` 행이 없어 빈 표 |

평가원에게는 「배포는 됐는데 아무것도 없는 서비스」로 보입니다.
`db/seed_demo_persona.sql` 이 정확히 이 문제 때문에 있는 파일입니다 —
계정 · 라이프로그 30일치 · 위기 점수를 한 번에 넣습니다.

---

## 1단계 — 시드를 넣습니다

서버 접속 콘솔(NCP 콘솔 → 서버 → 접속 콘솔, `.pem` 불필요)에서 실행합니다.

```bash
cd ~/lisn/infra
docker compose exec -T postgres psql -U postgres -d lisn < ~/lisn/db/seed_demo_persona.sql
```

계정은 `demo.crisis@lisn-test.example` 로 생깁니다. 역할은 `USER` 입니다.

## 2단계 — 비밀번호를 바꿉니다 (건너뛰지 마세요)

시드의 비밀번호는 **공개 저장소 주석에 평문으로 있습니다**
(`db/seed_demo_persona.sql:67`). 그대로 두면 누구나 로그인할 수 있습니다.

```bash
cd ~/lisn/infra
docker compose exec backend python -c "from app.core.security import hash_password; print(hash_password('<새 비밀번호>'))"
```

출력된 해시를 그대로 넣습니다.

```bash
docker compose exec postgres psql -U postgres -d lisn \
  -c "UPDATE users SET password_hash='<붙여넣기>' WHERE email='demo.crisis@lisn-test.example';"
```

비밀번호 규칙은 **8~64자 · UTF-8 72바이트 이하**뿐입니다
(`backend/app/schemas/common.py:41`). 문자 종류 제약은 없습니다.

## 3단계 — ADMIN 으로 올립니다

관제 웹은 앱과 같은 로그인 API 를 쓰고 `ADMIN` 역할만 세션을 허용합니다.
이걸 건너뛰면 **앱만 되고 관제 화면은 못 봅니다.**

```bash
docker compose exec postgres psql -U postgres -d lisn \
  -c "UPDATE users SET role='ADMIN' WHERE email='demo.crisis@lisn-test.example';"
```

- 테이블명은 **소문자 `users`** 입니다(`db/schema.sql:24`)
- `CHECK (role IN ('USER','ADMIN'))` 이라 오타는 제약에 걸립니다
- ⚠ **API 로는 ADMIN 을 만들 수 없습니다.** `signup` 이 `role` 을 넘기지 않아
  DB 기본값으로 굳습니다. 의도된 설계이니 되돌리지 마세요

## 4단계 — 날짜가 흘러도 화면이 살아 있게 합니다

시드는 `collected_at` 을 `now()` 기준 상대값으로 넣습니다. **자정을 넘기면
가장 최근 기록이 「어제」가 되고 홈 화면이 다시 `-` 로 돌아갑니다.**
평가원은 본인 일정대로 들어오니 이대로 두면 안 됩니다.

`db/refresh_demo_persona.sql` 이 기록 전체를 **같은 간격만큼 앞으로 밀어**
가장 최근 기록을 항상 「지금」으로 맞춥니다. 곡선 모양과 기록 간격은
그대로 보존되고, 행을 지우지 않으므로 **`user_id` 가 바뀌지 않아 세션이
끊기지 않습니다.**

```bash
cd ~/lisn/infra
docker compose exec -T postgres psql -U postgres -d lisn < ~/lisn/db/refresh_demo_persona.sql
```

며칠 걸러 돌려도 한 번에 따라잡습니다. 현재 시각과의 차이를 재서 밀기
때문입니다. 심사 기간 내내 열어둘 것이므로 **매일 새벽에 걸어 둡니다.**

```bash
( crontab -l 2>/dev/null; \
  echo "10 4 * * * cd ~/lisn/infra && docker compose exec -T postgres psql -U postgres -d lisn < ~/lisn/db/refresh_demo_persona.sql >> ~/lisn/refresh_demo.log 2>&1" \
) | crontab -
crontab -l
```

심사가 끝나면 `crontab -e` 로 이 줄을 지웁니다.

## 심사가 끝나면

```bash
crontab -e     # 갱신 줄 삭제
docker compose exec postgres psql -U postgres -d lisn \
  -c "DELETE FROM users WHERE email='demo.crisis@lisn-test.example';"
```

`ON DELETE CASCADE` 라 하위 기록이 함께 지워집니다.

## ⚠ 따로 남기는 사실 — 공개 저장소의 평문 비밀번호

`db/seed_demo_persona.sql:67` 의 주석이 팀 공용 테스트 비밀번호를 평문으로
갖고 있습니다. 저장소가 공개라 이미 노출된 상태입니다. 2단계에서 운영
계정의 비밀번호를 바꾸면 **이 경로는 닫힙니다.** 다만

- 주석을 지워도 **이미 커밋된 이력에는 남습니다**
- 같은 비밀번호를 다른 곳에 쓰고 있다면 그쪽을 바꿔야 합니다

심사 자체에는 영향이 없으나 알고는 있어야 합니다.
