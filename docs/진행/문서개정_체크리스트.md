## 3. 표기 규칙

- **[교체]** 해당 문장/항목을 통째로 바꿈 · **[추가]** 기존 내용 뒤에 덧붙임 · **[확인]** 사실관계 확인 후 판단
- ⭐ 심사 방어에 직결 · ⭐⭐ 그중에서도 우선

> ### ⚠ PPTX 를 저장할 때
> 다시 저장하면 **임베드 폰트가 풀릴 수 있습니다**(5.99MB → 305KB, 폰트 6개 → 0개로 실제 발생). `파일 → 옵션 → 저장 → 파일에 글꼴 포함` 을 확인하세요.
>
> 텍스트만 바꾸는 것이라면 `tools/patch-pptx-text.ps1` 처럼 **XML 을 직접 고치는 편이 안전합니다.** 서식을 건드리지 않아 폰트가 풀리지 않습니다.

> ### ⚠ 붙여넣을 때마다 확인하세요
> 실제로 다섯 번 다 사고가 났습니다.
> 1. **마크다운 기호** — `**굵게**` 의 별표, `` `코드` `` 의 백틱이 딸려 들어갑니다
> 2. **스마트 따옴표** — 한글이 `'FRIEND'` 를 `'FRIEND’` 로 바꿉니다. **SQL 이 실행되지 않습니다**
> 3. **고칠 때 한 글자 더 지우기** — 따옴표를 고치다 옆의 정상 따옴표까지 지워 `IN ('FRIEND,` 가 된 적이 있습니다
> 4. **앞뒤 줄까지 붙여넣기** — 코드 블록이 위치를 잡으려고 **앞뒤 줄을 함께 보여줄 때가 있습니다.** 그 줄들은 이미 문서에 있으니 빼고 붙여넣으세요
> 5. **글자 조각이 남기** — 비고를 고치다 `heart_rate` 의 조각인 `eart_rat` 가 남은 적이 있습니다. **고친 칸은 끝까지 읽으세요**

> ### ⚠ 축약 표기를 그대로 옮기지 마세요
> 표 안에서 자리를 아끼려고 `단위 + DEFAULT 0` 처럼 줄여 쓴 것이 문서에 그대로 들어간 적이 있습니다. 실제로 들어갈 값은 `단위: m, DEFAULT 0` 이었습니다.
>
> **작성 측 규칙** — 표의 「교체」 칸에는 **문서에 들어갈 문자열을 그대로** 적는다. 설명이 필요하면 표 밖에 쓴다.

> ### ⚠ 반영 여부를 문구 검색으로만 판정하지 마세요
> **grep 0건이 미반영을 뜻하지 않습니다.** `01-G`·`01-H②` 가 처음 0건으로 나왔는데 실제로는 반영돼 있었고 **줄바꿈이 문구를 쪼갠 것**이었습니다(`앱에서 최소 15분` / `간격 전송`). 반드시 절 전체를 읽어 확인하세요.
>
> **반대로 검색이 오탐을 낼 수도 있습니다.** 기획서의 `혈압` 1건은 활용방안이 아니라 **시장 현황의 통계 인용**(한국미디어패널조사)이라 문제없었습니다.

## 4. 문서를 고친 뒤

1. **HWP 를 고쳤으면 PDF 로 다시 내보냅니다.** `tools/doc2txt.py` 는 HWP 를 읽지 않아서, PDF 를 새로 뽑지 않으면 추출본이 옛 내용 그대로입니다

3. **원본과 추출본을 같은 커밋에** 넣습니다. 그래야 버전 간 diff 가 보입니다

> 실제로 PDF 는 최신본인데 추출본은 이전 판인 커밋이 나온 적이 있습니다(`7922122`). 재추출을 건너뛰면 다음 사람이 옛 내용을 근거로 판단하게 됩니다.
