### ✅ 알림 겹침 검사 — 발견하고 같은 날 닫았습니다 (2026.08.06)

요구사항정의서 `MLCM_220` ※ 주석이 규정하는데 구현에 없었습니다.

> ※ … 트리거·전달 내용·빈도 제한이 모두 다르며, **같은 날 두 알림이
> 겹치면 `MLCM_220` 을 보내지 않는다.**

`_blocking_reason` 의 사유가 다섯뿐이었습니다 — `risk_critical` ·
`user_없음` · `케어알림_미동의` · `발송시간_아님` · `쿨다운_중`.

**`콘텐츠알림_겹침` 을 추가했습니다.**

| 보는 것 | 왜 |
|---|---|
| 이번 판정이 `CONTENT` 액션인가 | `MLCM_400` 은 `CAUTION` 판정 시점에 콘텐츠를 전달합니다 |
| 오늘(KST) 적재된 `CAUTION` 판정이 있는가 | 하루에 판정이 여러 번 옵니다. 오전에 나간 알림을 놓치면 안 됩니다 |
| `content_alert_agreed` | **꺼둔 사람에게는 푸시가 안 나가므로 겹칠 것이 없습니다** |

**세 번째가 중요합니다.** 이걸 빼면 알림을 줄이려던 사람이 선제 접촉까지
잃습니다. 끈 것은 콘텐츠 쪽인데 안부 인사가 막히는 것이고, **알림을 끄는
사람일수록 앱을 안 여는 사람**이라 손실이 큽니다.

**두 곳을 봅니다** — 지금 들고 있는 판정과 오늘 적재된 판정. `analysis.py` 는
판정을 커밋한 뒤에 부르므로 DB 조회만으로 충분하지만, 그러면 **호출 순서에
조용히 의존**하게 됩니다. 트랜잭션을 합치는 순간 검사가 사라집니다.

#### 부수 효과 — `CAUTION` 인 날에는 선제 접촉이 안 갑니다

문서가 의도한 결과입니다. 「위험 단계와 무관하게」는 **트리거**가 위험
단계가 아니라 기준선 이탈이라는 뜻이고, 겹침 규칙은 별개의 빈도 상한입니다.
선제 접촉의 본래 자리는 **이탈은 이어지는데 위험 단계는 `NORMAL`** 인
상태입니다 — 그날은 콘텐츠 추천도 안 뜨므로 다른 경로가 없습니다.

> ⚠ 테스트 기본값도 `CAUTION` → `NORMAL` 로 바꿨습니다. 안 바꾸면 다른
> 조건을 재려는 테스트가 죄다 `콘텐츠알림_겹침` 으로 떨어집니다.

#### ⚠ FCM 이 붙으면 다시 볼 것

지금은 **판정 단계를 대리값으로** 씁니다. 실제 발송 기록이 없기 때문입니다.
콘텐츠 푸시가 붙은 뒤 **판정은 `CAUTION` 인데 푸시는 안 나가는 경우**(추천할
콘텐츠가 없음 · 발송 실패)가 생기면, 겹치지도 않았는데 선제 접촉이 막힙니다.
그때는 대리값 대신 **실제 발송 기록**을 봐야 합니다.

`health` 13.3.1 의 Android 지원 타입을 확인한 결과입니다.

| `BODY_COMPOSITION_METRICS` 컬럼 | Health Connect | 판정 |
|---|---|---|
| `weight_kg` | `WEIGHT` | ✅ 직접 |
| `body_water_kg` | `BODY_WATER_MASS` | ✅ 직접 |
| `bmr_kcal` | `BASAL_ENERGY_BURNED` | ✅ 직접 |
| `body_fat_kg` | `BODY_FAT_PERCENTAGE` | ⚠ **단위가 %** — `weight_kg × pct/100` 로 환산해야 하고, 체중이 없으면 못 구합니다 |
| `muscle_mass_kg` | **없음** | ❌ |
| `muscle_mass_min_kg` · `max_kg` | **없음** | ❌ 체성분계 표준범위라 플랫폼에 개념 자체가 없습니다 |
| `skeletal_muscle_kg` | **없음** | ❌ |

**⚠ `LEAN_BODY_MASS` 를 `muscle_mass_kg` 에 매핑하면 안 됩니다.** 제지방량은
근육 + 뼈 + 수분 + 장기라서 근육량과 다른 값입니다. 이름이 비슷하다고 넣으면
**틀린 숫자가 화면에 뜹니다.**

화면설계서 `MAIN_LIFELOG_01` ❺ 는 "체중·체지방·**근육량**·기초대사량"을
명시하는데, **근육량이 Health Connect 로는 안 옵니다.**

**✅ A안 확정 (2026.08.03)** — Health Connect 로 채워지는 4개만 수집하고
화면설계서 ❺ 의 「근육량」을 「체수분」으로 바꿉니다(개정안 `PL-26`).
**테이블은 그대로 둡니다** — 기업 제공 데이터에는 8개가 전부 있고 분석은
그걸로 하므로, 컬럼을 지우면 학습 데이터 규격과 어긋납니다.

> **이번에 처음 드러난 것** — **실서비스 수집 경로(Health Connect)와 학습
> 데이터 출처(기업 정제본)의 항목이 다릅니다.** 지금까지 어느 문서에도
> 적혀 있지 않았습니다. 기획서 4장에 한 줄 명시하도록 개정안에 담았습니다.

**✅ 구현 완료 (2026.08.03)**

| | |
|---|---|
| `health_reader.dart` | `WEIGHT`·`BODY_FAT_PERCENTAGE`·`BODY_WATER_MASS`·`BASAL_ENERGY_BURNED` 추가 |

**⚠ `POST /body-composition` 은 UPSERT 가 아니라 INSERT 입니다.**
`LIFELOG_METRICS` 에는 `uq_lifelog_user_collected` 가 있는데
`BODY_COMPOSITION_METRICS` 에는 대응 제약이 없습니다. 지금은 앱이

**환산 주의** — 스키마는 `body_fat_kg` 인데 Health Connect 는

비웁니다.** 퍼센트를 kg 칸에 그대로 넣으면 「체지방 22kg」이 「22%」로
뒤바뀝니다.
