**분석 파이프라인이 끝까지 관통합니다.** AI 서버 스텁으로 검증했습니다.

```
앱 push → UPSERT → 백그라운드 분석 트리거 → AI 서버 판정
       → EMOTION_RISK_SCORES → 홈 action 자동 전환 → 리포트 반영
```

AI 서버가 없어도 push 는 성공합니다. 분석 실패로 되돌리면 라이프로그가 유실됩니다.

전부 **실제 서버로 검증**했습니다. 검증 내역은 [`작업이력.md`](review/작업이력.md) 22·23차.

### LLM 경로 — Gemini 로 검증 완료 (2026.08.01)

**2차 문맥 판정이 실제로 돕니다.** 관용 표현("배고파 죽겠다")을 LLM 이 `NORMAL` 로 걸러내는
것까지 확인했습니다. 실측값은 [`docs/llm/USAGE_LOG.md`](llm/USAGE_LOG.md) LLM-004.

`.env` 의 `LLM_PROVIDER` 로 갈아탑니다. 평소 개발은 **Gemini**(무료 한도), 정확도 검사·
시연은 **OpenAI**.

> ⚠ **Gemini 는 임시 수단입니다.** 산출 문서(01 기획서 · 02 `MLCM_310`/`MLCM_320`)의
> **"외부 OpenAI API" 가 정본**이고 문서는 고치지 않습니다. **OpenAI 경로를 죽이지 마세요.**

- Gemini 는 OpenAI 호환 엔드포인트라 SDK 는 `openai` 를 그대로 씁니다. 다만
  **Responses API 미지원**이라 양쪽 다 Chat Completions 로 통일했습니다
- **작업마다 다른 모델**을 씁니다. 무료 한도가 모델별로 잡혀서 한 모델에 몰면 병목입니다.
  특히 `reply`·`crisis` 는 `analyze_and_reply` 에서 **동시 호출**되므로 반드시 갈라놓습니다
- **`max_retries=0` 을 되돌리지 마세요.** 무료 티어는 모델이 통째로 503 이 되는 일이 있고,
  기본 재시도(2회)면 죽은 모델 하나가 `NFR-DV-001` 3초 예산을 통째로 먹습니다(실측 13.95초)

### `USERS.role` 을 왜 넣었나

관리자 기능이 `MLCM_501` · `FR-MN-003` · `MLCM_510` · 04 접근통제 · 발표자료 slide5 에 모두 있는데 **데이터 모델에 관리자 개념이 없었습니다.** 판별 수단이 없어 `MLCM_501` 을 구현할 수 없는 상태였습니다. 이 컬럼이 `02-F`(6) 의 *"접근통제(본인 및 권한 있는 관리자로 제한)"* 방어 논리도 완성합니다.

### PPTX 를 코드로 고치는 법

`tools/patch-pptx-text.ps1` 이 예시입니다. **한글·PowerPoint 로 다시 저장하면 임베드 폰트가 풀리는데, XML 을 직접 고치면 그 위험이 없습니다.**

- `<a:t>` 안의 글자만 바꾸고 `<a:rPr>`(서식)은 건드리지 않으므로 폰트·크기가 그대로 유지됩니다
- **교체는 정확히 1건 매칭될 때만 적용**하도록 짰습니다. 0건이면 건너뛰고 보고하므로 재실행해도 안전합니다
- 적용 후 반드시 검증하세요 — 슬라이드 수, 전체 파트 수, 각 슬라이드 XML 파싱
