## ⭐ 1. 보안 — 「전부 암호화」가 아니라 **위험도 기반**입니다

**이게 가장 좋은 이야깃거리입니다.** 「다 암호화했습니다」보다
**「무엇을 왜 암호화하지 않았는지 설명할 수 있다」**가 훨씬 강합니다.

### 실제로 넣은 것

| 계층 | 무엇 | 근거 |
|---|---|---|
| 전송 구간 | **HTTPS/TLS** — 앱↔백엔드, 백엔드↔AI 서버 | `NFR-DE-002` (1) |
| 저장 매체 | DB 볼륨 디스크 암호화(클라우드 배포 시) | `NFR-DE-002` (2) |
| **컬럼 단위** | **AES-256-GCM** — `USERS.phone` | `core/crypto.py` |
| 비밀번호 | **bcrypt** — 복호화하지 않음 | `core/security.py:63` |
| 대화 저장 | **정규식 PII 마스킹** — 전화·주민번호·이메일 | `services/safety.py` |
| 식별자 | **UUID v4** — 테이블 10곳 전부 | `schema.sql` `gen_random_uuid()` |

### 왜 「전 컬럼 암호화」를 안 했나 — 이 대답이 핵심입니다

> **라이프로그 측정치를 컬럼 암호화하면 서비스가 동작하지 않습니다.**
> 기간별 집계와 복합 인덱스가 핵심 동작인데, 암호화하면 **범위 조회를
> 할 수 없습니다.** 그래서 유출 시 **즉각적 2차 피해**가 나는 항목
> (연락처)만 컬럼 암호화하고, 측정치는 전송 구간 보호와 접근통제로
> 지킵니다.

**「보안을 덜 했다」가 아니라 「보안 요구를 기능 제약과 함께 설계했다」**입니다.
초기에는 전 컬럼 AES-256 이었는데 **안건 4** 에서 바꾼 결정입니다.

### UUID v4 를 쓴 이유

```sql
user_id UUID PRIMARY KEY DEFAULT gen_random_uuid()
```

**순번 PK 를 쓰면 `/users/1`, `/users/2` 로 남의 데이터를 훑을 수 있습니다.**
건강 데이터라 그 위험이 특히 큽니다. UUID 는 추측이 불가능합니다.

⚠ **「UUID 라서 보안이 된다」고 말하지 마세요.** 접근 제어는 JWT + `user_id`
대조로 따로 합니다(`_load_session` 이 `user_id` 를 함께 걸어 타인 세션
접근을 막습니다). UUID 는 **열거 공격을 막는 것**이지 인가가 아닙니다.

### 마스킹은 저장 **전에** 합니다

```
사용자 발화 → mask_pii() → DB 저장 · LLM 전송
```

**마스킹된 텍스트를 저장하고 LLM 에도 그것을 보냅니다.** 원문은 어디에도
남지 않습니다. 「외부 API 에 개인정보가 나가나요」에 대한 답입니다.

## 2. 아키텍처 — 왜 서버를 둘로 나눴나

```
Flutter 앱 ─→ 비즈니스 서버(FastAPI)  ─→ AI 추론 서버(FastAPI)
                    │                        └ 개인 기준선 이탈 탐지
                    └ 인증 · 대화 · 위기 키워드 · 정책
```

- **대용량 시계열 적재**와 **LLM 추론**이 서로 부하를 밀어내지 않게
- **위기 키워드 필터는 비즈니스 서버 안**에 둡니다 — AI 서버가 죽어도
  탐지가 멈추면 안 되기 때문입니다(`NFR-DV-003`)

### 앱이 **밀어 올리는** 구조 — 서버가 끌어오지 않습니다

**Health Connect 는 Android 단말 안의 권한 모델**이라 **서버가 가질 수 있는
OAuth 토큰이 없습니다.** 그래서 앱이 읽어서 서버로 push 합니다(**안건 1-1**).

> 「왜 서버에서 주기적으로 가져오지 않나요」에 대한 답입니다. **못 하는
> 것이지 안 한 것이 아닙니다.**

## ⭐ 3. 안전 설계 — 정신건강 서비스라서 다르게 만든 것

### ① 위기 탐지가 2단계인 이유

```
1차  키워드 규칙 (백엔드 내장)   외부 API 가 죽어도 동작
2차  LLM 문맥 판정               오탐을 줄이는 정밀 판정
```

**키워드 단독 재현율은 0.081 이고 2단계가 0.793 까지 올립니다.** 그런데도
1차를 남긴 이유는 **API 장애 때 탐지가 0 이 되면 안 되기 때문**입니다.

### ② CRITICAL 이면 생성한 답변을 **버립니다**

```python
if risk.action == "EMERGENCY":
    reply = None          # 만들어둔 일반 응답을 폐기
```

**그래서 스트리밍을 쓰지 않습니다.** 판정 전에 흘린 글자는 회수할 수
없습니다. 응답 속도보다 **잘못된 말이 나가지 않는 것**을 택했습니다.

### ③ 정신건강 화면에 **경고색을 쓰지 않습니다**

빨강·주황은 **불안을 키워 회피를 유발합니다.** 주목도는 색이 아니라
**배치와 구조**로 만듭니다. 라이프로그의 「최종 동기화 5시간 전」도
경고색 없이 시간만 적습니다.

### ④ 데이터가 없을 때 **「정상」이라고 하지 않습니다**

```
실측치 3일 미만 → 422 로 끊음
```

**편차 0 을 「정상」으로 적재하면 관제 대시보드에서 위험을 놓칩니다.**
「없는 것」과 「괜찮은 것」을 구분합니다.

## ⭐ 4. 선제 접촉 — 차별점입니다

**경쟁 서비스는 감지 결과를 사용자가 앱을 열어야 확인합니다.**
우리는 **시스템이 먼저 말을 겁니다.**

```
라이프로그 → 판정 → 연속 이탈 3일 → 조건 6개 검사 → 첫 발화 생성
                                          → 세션 선생성 → 홈 카드·배너
```

### 「감시 아닌가요」에 대한 답 — 장치를 넣었습니다

| 장치 | 무엇 |
|---|---|
| **옵트인** | 케어 알림 동의를 콘텐츠 알림과 **따로** 받습니다 |
| **빈도 상한** | 쿨다운 3일 · 하루 1회 · 09~21시 |
| **겹침 방지** | 같은 날 콘텐츠 알림이 나가면 선제 접촉은 보내지 않습니다 |
| **근거 제시** | 「왜 말을 걸었는지」를 첫 마디에 담습니다 |
| **내부 용어 차단** | `수면효율` → 「잠의 깊이」로 바꿔 말합니다 |

> **「수면효율이 62%로 낮아졌어요」는 감시입니다.** 「요즘 잠이 얕아지신
> 것 같아요」는 안부입니다. 같은 데이터인데 다르게 읽힙니다.

### 보내지 **않은 것도** 기록합니다

`OUTREACH_LOGS` 에 `SKIPPED` 와 사유를 남깁니다. 안 남기면 **「왜 안
왔지」에 답할 수 없습니다.**

## 5. 검증 — 「돌아갑니다」를 숫자로

```
회귀 테스트   296건   backend 107 · AI 22 · 앱 153 · 관리자 웹 14
문서 검사기    4종    수치·중복·붙여넣기·화면 대조
평가셋        211건   사람이 작성 · 2인 교차 라벨링
```

### 문서를 기계가 검사합니다

**같은 숫자가 여러 문서에 흩어져 있으면 반드시 갈립니다.** 실제로 하루에
「API 30 vs 33」·「테이블 8 vs 9」·「평가셋 200 vs 211」이 나왔습니다.

```powershell
python tools/check_numbers.py    # 문서 간 수치가 서로 맞는가
```

> **「다음엔 더 꼼꼼히 보겠습니다」는 해결책이 아닙니다.** 세는 일을 사람이
> 하지 않게 만드는 것이 해결책입니다. **이 태도 자체가 발표 재료입니다.**

### 스키마가 정본이고 코드가 따라갑니다

`db/schema.sql` 하나가 정본이고, `test_schema_drift.py` 가 **모델과
어긋나면 실패**시킵니다. 정본이 둘이 되면 문서와 대조할 기준이 사라집니다.

## ⭐ 6. 못 한 것을 그대로 말하는 것 — 이것도 재료입니다

**감추면 질문 한 번에 무너집니다. 먼저 말하면 태도가 됩니다.**

| 무엇 | 어떻게 말하나 |
|---|---|
| 재현율 0.793 (목표 0.90 미달) | **그대로 보고합니다.** 미탐 23건이 완곡·작별·신변 정리에 몰려 있고, 같은 문장을 2인이 라벨링해도 갈립니다(κ 0.388) |
| 그래서 무엇을 했나 | **프롬프트를 더 고치지 않았습니다** — holdout 이 없어 평가셋에 과적합됩니다. 대신 **확인 질문으로 문맥을 확보**하는 쪽으로 설계했습니다 |
| 분류 모델 미채택 | 라벨 있는 데이터셋을 못 구했고, 공개 데이터로 검증하니 **ROC-AUC 0.528**(무작위 수준)이었습니다. **검증하고 접었습니다** |
| iOS 제외 | **장비·계정·일정** 때문입니다. 기술적으로 불가능한 게 아닙니다 |
| FCM 미구현 | 자격증명 문제입니다. **없어도 앱을 열면 닿습니다** — 홈 카드와 배너 |

> **「할 수 있는데 안 했다」가 「몰라서 안 했다」보다 낫습니다.**
