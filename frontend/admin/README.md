# 관리자 관제 웹

> **최종 점검** 2026.08.02

React + Vite 기반 관제 도구입니다. `ADMIN_LOGIN_01` · `ADMIN_DASH_01` 두 화면이고,
**관제 3개 탭이 전부 실제 API 에 붙어 있습니다.**

```powershell
npm install
npm run dev
```

기본 API 주소는 `http://localhost:8000/api/v1`입니다. 다른 주소는 환경변수로 지정합니다.

```powershell
$env:VITE_API_BASE_URL='http://localhost:8000/api/v1'
npm run dev
```

> ⚠ **토큰이 만료되면 로그인 화면으로 돌아갑니다.** 401 을 받으면 세션을 버리고
> 「로그인 유효 시간이 지났습니다」를 띄웁니다. 403(권한 없음)은 재로그인해도
> 해결되지 않으므로 세션을 버리지 않습니다.

> ⚠ **5173 포트여야 합니다.** 백엔드 `CORS_ORIGINS` 가 그 주소만 허용합니다. 이전 vite
> 인스턴스가 5173 을 잡고 있으면 새 창이 **5174 로 뜨고 요청이 전부 CORS 로 막힙니다.**
> 400 이 계속 나면 주소창의 포트부터 보세요.

## 화면

| 탭 | 내용 | 유스케이스 |
|---|---|---|
| 관제 대시보드 | 위험도 분포 · 평가/미평가 인원 | `MLCM_501` ❶ |
| 대상자 조회 | 위험도 필터 · 이름·이메일 검색 · **행을 누르면 상세** | `MLCM_501` ❷❸ |
| 위기 사건 이력 | `CRITICAL` 판정 기록 | `MLCM_501` ❹ · `MLCM_510` |

### 대상자 상세는 앱과 같은 시각화 규격입니다

`MLCM_501` 4단계가 「`MLCM_500` 과 동일한 시각화 컴포넌트 재사용」을 요구합니다.
스택이 달라 컴포넌트 자체는 공유할 수 없으므로 **규격을 맞춥니다**(`Report.jsx`).

| 맞춰야 할 것 | 값 |
|---|---|
| 감정 곡선 축 | **0~100 고정.** 데이터 범위로 정규화하면 62~65 의 미미한 흔들림이 급등락으로 보입니다 |
| 위험 단계 색 | 안정 `#5b8d83` · 주의 `#6289b1` · 심각 `#987466` |
| 점 색 | 서버가 준 `risk_level` 로 칠합니다. **점수로 다시 판정하지 않습니다** |

앱의 `report_screen.dart` 를 고치면 여기도 함께 보세요. 반대도 마찬가지입니다.

> 라이프로그는 명세상 감정 추이와 **같은 시간축에 겹치는 것**이지만, 단위가 달라
> 한 좌표계에 그리면 둘 다 못 읽습니다. 같은 기간의 요약값을 나란히 두는 것으로
> 갈음했습니다. 값이 없으면 0 이 아니라 **「측정 안 됨」**입니다.

> 연락처로는 검색할 수 없습니다. `phone` 이 AES-256-GCM 컬럼 암호화라 같은 값도
> 암호문이 매번 달라 부분 일치가 성립하지 않습니다(02-F 3항 · 안건 4).

## 인증

로그인은 Flutter 앱과 같은 `POST /auth/login`을 씁니다. **별도 인증 체계를 만들지
않습니다** — 관리자 전용 로그인 로직을 따로 두면 인증 체계가 둘로 갈립니다.

토큰은 브라우저 탭을 닫으면 사라지는 `sessionStorage` 에 보관합니다.

> **`role` 승격은 API 에 즉시 반영됩니다.** 서버의 `require_admin` 이 JWT 클레임이
> 아니라 DB 의 `USERS.role` 을 읽기 때문입니다.
>
> **다만 이 화면은 재로그인해야 합니다.** `saveAdminSession` 이 로그인 응답의 role 로
> 저장 여부를 정해서, 승격 전에 로그인했다면 세션 자체가 없습니다.

## 화면이 튀지 않게 지킬 것

대상자 조회는 필터·검색으로 **행 수가 크게 변합니다.** 아래 네 가지를 되돌리면 누를
때마다 화면이 출렁입니다. 실제로 그랬고 실측해서 고쳤습니다.

| 지킬 것 | 되돌리면 |
|---|---|
| 조회 중 이전 목록 유지 (`is-pending` 으로 흐리게만) | 표가 사라졌다 돌아와 본문 높이가 1598→720→1598 로 두 번 튐 |
| `.data-table.people { table-layout: fixed }` | 결과가 바뀔 때마다 다섯 컬럼 폭이 전부 재계산됨 |
| `:root { scrollbar-gutter: stable }` | 스크롤바가 생겼다 없어지며 화면 전체가 좌우 15px 이동 |
| 지우기 버튼을 `visibility` 로만 숨기기 | 첫 글자에서 검색창 폭이 변해 오른쪽 정렬이 밀림 |

건수 안내 줄도 결과가 0건일 때 **공백으로 높이를 유지**합니다. 줄을 없애면 아래가
올라왔다 내려갑니다.

## 문구는 `labels.js` 로

`countLabel`·`emptyLabel` 에 넘기는 `query`·`filter` 는 **지금 화면에 그려진 목록을
만들어낸 조건**이어야 합니다. 살아 있는 입력값을 넘기면 다시 불러오는 동안
`"하늘" 검색 결과 33명` 같은 없는 상태가 만들어집니다.

그래서 `PeopleTab` 은 결과를 `{ items, query, filter }` 로 함께 담습니다.

## 판단 로직을 여기 두지 마세요

감정→위험도 매핑은 **서버가 확정**합니다(04 문서 6항). 응답의 `risk_level` 을 그대로
표시하고 점수로 다시 판정하지 않습니다.

평가 이력이 없으면 **「안정」이 아니라 「미평가」**입니다. 없는 것을 정상으로 표시하면
위험을 놓칩니다.

`model_version` 을 표에 노출하는 것도 의도한 것입니다. `rule-*` 이나
`seed-demo-*` 면 모델 결과가 아니라는 게 화면에서 구분돼야, 이 수치를 성능 근거로 쓰는
사고를 막습니다.
