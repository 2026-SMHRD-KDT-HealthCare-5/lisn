## 샘플로 어디까지 되는지 — 2026.08.01 실측

**같은 길을 다시 걷지 않도록 남깁니다.** 세 번 시도했고 전부 안 됐습니다.

| 시도 | 참가자 | 피처 | ROC-AUC | 판단 |
|---|---|---|---|---|
| 샘플 1개 | 10명 | 8 | **0.485** | 무작위 이하. 유효 fold 2개뿐이라 평가 자체가 불가 |
| 샘플 4개 | 40명 | 8 | **0.502** | fold 5개로 늘어 평가는 가능해졌으나 무작위 |
| 샘플 4개 | 40명 | 98 | **0.610** ±0.188 | fold별 `0.297~0.864` — 편차가 너무 큼 |
| **위를 20회 반복** | 40명 | 98 | **0.528** | **0.5 와 구분되지 않음** (20회 중 9회가 0.5 이하) |

**0.610 은 fold 운이었습니다.** 참가자를 바꿔가며 20회 반복하니 평균 0.528,
95% 구간이 `0.476 ~ 0.579` 로 0.5 를 포함합니다.

### ✅ 2026.08.02 재현 확인

**같은 결론이 다시 나왔습니다.** 저장소 코드로 그대로 돌린 값입니다.

| 재현 대상 | 기록 | 재현 | |
|---|---|---|---|
| 샘플 1개 · 10명 · 8피처 | 0.485 | **0.485** (±0.131, 2 folds) | 일치 |
| 샘플 4개 · 40명 · 8피처 | 0.502 | **0.502** (±0.112, 5 folds) | 일치 |

20회 반복도 **8피처 데이터로 따로 돌려** 확인했습니다(98피처 행렬은 저장소에
없어 그대로는 못 돌립니다).

```
20회 반복 · 참가자를 섞어 fold 재구성
  평균 ROC-AUC   0.535
  95% 구간       0.445 ~ 0.592     ← 0.5 를 포함
  0.5 이하       3 / 20 회
  최소~최대      0.428 ~ 0.594
```

**98피처(0.528)와 8피처(0.535)가 사실상 같습니다.** 피처를 12배 늘려도
달라지지 않는다는 뜻이고, 문제가 피처가 아니라 **참가자 수**라는 진단을
뒷받침합니다.

### ⚠⚠ 그런데 더 근본적인 문제가 있습니다 — 9종 감정 라벨이 없습니다

위 실측은 전부 **이진 우울 분류**(`dep`)입니다. `MLCM_210` 3단계가 요구하는
것은 그게 아닙니다.

> 2단계(LightGBM): ... **9개 감정 코드(EMOTIONS) 중 하나를 emotion_id 로 분류**하고

**공개 샘플에 9종 감정 라벨이 없습니다.**

| 데이터에 있는 것 | 값 |
|---|---|
| `BDI2` | Beck 우울척도 원점수 (0~39) |
| `dep` | 위를 이진화한 우울 여부 |
| 감정 코드 | **열 자체가 없음** |

BDI-2 는 **우울 정도를 재는 척도**이지 감정 종류를 구분하는 라벨이 아닙니다.
기쁨·즐거움·행복·슬픔·불안·외로움·분노·절망·위기를 가르려면 그 라벨이 붙은
데이터가 있어야 하는데, GLOBEM·PMData 둘 다 갖고 있지 않습니다.

**즉 9종 분류는 성능이 낮은 게 아니라 학습을 시작할 수조차 없습니다.**

### 지금 규칙 판정이 실제로 하는 일

```python
if anomaly >= 0.5:    emotion_code = "SADNESS"
elif anomaly >= 0.25: emotion_code = "ANXIETY"
else:                 emotion_code = "HAPPINESS"
```

`anomaly` 는 **수면 부족 + 활동량 감소** 하나짜리 축입니다. 그 축을 두 번
잘라 3종만 씁니다.

**나머지 6종(JOY·DELIGHT·LONELINESS·ANGER·DESPAIR·CRISIS)은 라이프로그
경로에서 절대 나오지 않습니다.** `DESPAIR`·`CRISIS` 는 대화 쪽 위기 탐지가
따로 처리합니다.

> 걸음 수와 수면 시간으로 **외로움과 분노를 구분할 수 있는가** — 이 질문에
> 답할 근거가 지금 없습니다. 있다고 주장하면 안 됩니다.

### ✅ 다른 데이터로도 확인했습니다 (2026.08.02)

「40명이 적어서 안 된 것 아니냐」를 확인하려고 **LifeSnaps**
(Zenodo 7229547, CC-BY 4.0)로 같은 조건에서 돌렸습니다. 63명 · 2290일 ·
피처 65개 · 감정 라벨 7종을 **직접** 씁니다.

| 감정 | 평균 AUC | 95% 구간 |
|---|---|---|
| HAPPY | 0.540 | 0.525 ~ 0.556 |
| TIRED | 0.533 | 0.512 ~ 0.551 |
| NEUTRAL | 0.527 | 0.496 ~ 0.554 |
| RESTED/RELAXED | 0.518 | 0.493 ~ 0.544 |
| TENSE/ANXIOUS | 0.497 | 0.471 ~ 0.514 |
| SAD | 0.485 | 0.457 ~ 0.517 |
| ALERT | 0.479 | 0.435 ~ 0.512 |

**참가자 1.6배, 피처 8배, 감정 라벨 직접 사용 — 그래도 0.48~0.54 입니다.**

정작 잡아야 하는 `SAD`(0.485)·`TENSE/ANXIOUS`(0.497)가 0.5 아래입니다.
0.5 를 넘긴 `TIRED` 는 **수면 시간과 직접 이어진 감정**이라 거의
동어반복입니다 — 「어제 못 잤으니 피곤하다」를 맞힌 것이지 정서 추정이
아닙니다.

> 걸음·수면이 잡는 것은 **각성도**(피곤/각성)이고 **정서가**(슬픔/불안)는
> 거의 못 잡습니다. 표에 그 패턴이 그대로 보입니다.

재현: `python ai/train/eval_lifesnaps.py`
(데이터는 `ai/data_raw/` 라 커밋되지 않습니다 → 안내는
[`감정라벨_데이터_후보_20260802.md`](../docs/검증/감정라벨_데이터_후보_20260802.md))

### 그럼 문서를 고쳐야 하나

**고치지 않습니다.** `MLCM_210` 은 목표 설계이고, 지금은 그 설계의 파이프라인
자리를 규칙으로 채워둔 상태입니다. `model_version` 이
`rule-` 로 시작하는 것이 그 표시입니다(현재 `rule-baseline-v1`).

발표에서는 **「설계는 9종, 구현은 3종 규칙, 이유는 라벨 부재」** 로 말하는 것이
정확합니다. 9종을 분류하고 있다고 하면 안 됩니다.

### 왜 안 나오나

참가자 40명이면 fold 하나에 8명, 그중 양성이 3~4명입니다. **한 사람이 fold
전체 지표를 좌우합니다.** fold별 편차가 0.297~0.864 로 벌어진 게 그 증거입니다.
전체 데이터는 **497명** — 12배 차이입니다.

### 그래도 얻은 것

**"성능이 나쁘다"고 말할 수 있게 됐습니다.** 샘플 1개일 때는 유효 fold 가
2개뿐이라 그 말조차 근거가 없었습니다. 지금은 원인이 참가자 수임을 근거를 갖고
말할 수 있습니다.

> ⚠ **참가자 단위 분할(`GroupKFold`)을 무작위 분할로 바꾸지 마세요.**
> 14일 히스토리 피처라 같은 사람의 연속된 날짜끼리 값이 거의 같습니다.
> 무작위로 나누면 같은 사람이 학습·평가 양쪽에 들어가 **AUC 가 0.9 를 넘습니다.**
> 그 숫자를 믿고 진행하면 전체 데이터에서 무너집니다.

> 항목으로 학습하면 배포 시 그 자리가 비어 성능이 나오지 않습니다.
> 이유는 그 파일 주석에 적혀 있습니다 — 되살리기 전에 읽으세요.

## ⚠ 문서 작성 시 주의할 점

### 1. `hrv_sdnn` 은 진짜 SDNN 이 아닙니다

`process_pmdata.py` 는 **일별 BPM 의 표준편차**를 HRV 프록시로 씁니다.

```python
hrv_sdnn=('bpm', 'std')  # 심박수 표준편차 = HRV 프록시 지표
```

표준 SDNN 은 RR 간격(NN interval)의 표준편차인데, PMData 의 Fitbit 데이터에 RR 간격이 없어 대체한 것입니다. 합리적인 선택이지만 **산출물 문서에 그냥 "HRV"라고 쓰면 정확하지 않습니다.**

- **실서비스** — Health Connect 가 제공하는 HRV 를 그대로 수집
- **학습 데이터** — PMData 의 BPM 표준편차 프록시

두 값의 성격이 달라 **도메인 갭이 존재**합니다. 문서에 이 차이를 적어두면 "학습 데이터의 HRV 와 실제 수집하는 HRV 가 같은 건가요"라는 질문에 답할 수 있습니다.

### 2. GLOBEM 의 스크린타임 피처는 쓰지 않습니다 *(2026.07.29 제외)*

`process_globem.py` 가 원래 `screen.csv`(스크린타임·화면 잠금해제)를 병합하고 있었으나 **제거했습니다.**

**서비스가 만들 수 없는 피처로 학습하면 배포 시 그 자리가 비어 성능이 나오지 않습니다.**

- `LIFELOG_METRICS` 에 스크린타임 컬럼이 없습니다 (`db/schema.sql`)
- **Health Connect 는 스크린타임을 제공하지 않습니다.** 안드로이드에서 폰 사용량은 `UsageStatsManager` 영역이라 별도 권한이 필요하고, 현재 수집 범위·동의 항목 어디에도 없습니다

결과적으로 GLOBEM 피처 매트릭스는 **수면 4 + 걸음 4 + BDI-II 라벨 = 12컬럼**입니다. (이전 15컬럼)

> 폰 사용량을 정식 수집 항목으로 추가하기로 결정한다면, **스키마·요구사항정의서·동의 항목을 먼저 고친 뒤** 되살리세요. 순서를 바꾸면 "동의도 안 받은 데이터로 학습했다"가 됩니다.

### 3. 다른 공개 데이터셋을 검토했으나 추가하지 않았습니다

| 데이터셋 | 검토 결과 |
|---|---|
| **Depresjon** | **부적합.** 분 단위 활동량 하나뿐이라 수면·심박·HRV 와 겹치는 신호가 없습니다. MADRS 임상 라벨은 매력적이지만 신호가 없으면 쓸 수 없습니다 |
| **LifeSnaps** | **여유가 생기면 재검토.** Fitbit Sense 기반이라 GLOBEM 의 약점(심박·HRV 없음)을 메웁니다. 라벨이 PANAS(정서)·STAI(불안)이라 우울 척도보다 오히려 감정 9종 분류에 가깝습니다. 다만 실제 컬럼 구성 확인이 필요하고, 4주차 이후에나 볼 일입니다 |

**데이터셋을 하나로 합치는 것은 권장하지 않습니다.** 집계 단위(일별 vs 14일), 기기 모델, 라벨 척도(BDI-II·MADRS·PANAS 는 상호 변환 불가), 인구집단이 모두 달라 도메인 시프트가 큽니다. **지금처럼 역할을 나누는 구조**(PMData=비지도 1차, GLOBEM=지도 2차)가 맞습니다.

### 4. 현재는 전체 학습이 아니라 파이프라인 검증 단계입니다

| 스크립트 | 처리 범위 |
|---|---|
| `process_pmdata.py` | **참가자 `p01` 한 명** |
| `process_globem.py` | **`INS-W-sample_1` 샘플 1개** |

"전처리 완료"가 아니라 **"파이프라인 동작 확인 완료"** 입니다. 문서에 학습 규모를 쓸 때 과장하지 마세요.

## 기업(라라랩스) 제공 데이터 — 2026.07.29 메타데이터 수령

멘토가 전달한 [`라이프로그데이터_메타데이터`](../docs/extracted/라이프로그데이터_메타데이터.txt) 로 기존 질문 3건이 모두 해소되었습니다.

| 질문 | 답 |
|---|---|
| 항목과 단위 (초/분 원본 vs 일 통계) | **일(日) 단위 집계.** 날짜 `YYYY.MM.DD`, 수면 `min`, 걸음 `count`. **추가 전처리 불필요** |
| 정답(라벨) 데이터 유무 | ⚠ **없음.** 아래 참조 |
| 워치 미착용 구간 결측 처리 | 수면·깊은잠·얕은잠·REM 이 **기록되지 않은 행은 삭제**한 정제본 제공 |

### 제공 항목

- **라이프로그(13)** — 날짜, 깊은잠·얕은잠·각성·REM(min), 수면 시작·종료 시각, 활동 날짜·시작·종료 시각, 거리(m), 걸음 수, 칼로리
- **체성분(12)** — 회원번호, 나이, 성별, 키, 체중, 체수분, 체지방, 근육량 및 표준범위 상·하한, 골격근량, 기초대사량
- **집계(23)** — 위 항목에 총 수면시간·각성·입면 시간·수면 효율(%)·총 활동시간/거리/걸음수/칼로리 추가

### ⚠ "라벨링데이터" 에 정답이 없습니다

표 이름은 `라벨링데이터 항목` 이지만 **23개 항목이 전부 수면·활동·체성분 수치**입니다. 정서 상태나 위험도 라벨이 하나도 없습니다. **이름만 라벨링이고 실제로는 일별 집계 피처입니다.**

→ **2차 LightGBM 의 지도학습 정답은 GLOBEM 의 BDI-II 가 유일한 임상 라벨 소스입니다.** 기업 데이터로는 자체 위험도 점수를 산출해야 합니다(라이프로그 수치 가중치 방식).

### ⚠ 심박수·HRV 가 없습니다

기업 데이터 어디에도 심박수·HRV 가 없습니다. 출처별로 확보 수준이 다릅니다.

| 출처 | 심박수 | HRV |
|---|---|---|
| 기업 제공 데이터 | ❌ | ❌ |
| PMData | ✅ 분 단위 | △ 일별 표준편차 **프록시** |
| 실서비스 (Health Connect) | ✅ | ✅ |

→ **1차 모델은 수면·활동을 공통 피처로 쓰고, 심박·HRV 는 확보 가능한 구간의 보조 피처로 다룹니다.** 문서 반영은 체크리스트 `03-E`.
