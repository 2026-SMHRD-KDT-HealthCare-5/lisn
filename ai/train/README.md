## ⚠ 먼저 읽으세요 — 지금 나온 모델은 쓸 수 없습니다

`train_stage2.py` 는 **동작합니다.** 하지만 공개 샘플로 학습한 결과는 **예측력이 없습니다.**

| 데이터 | 참가자 | 피처 | ROC-AUC |
|---|---|---|---|
| 샘플 1개 | 10명 | 8 | **0.485** (유효 fold 2개) |
| 샘플 4개 | 40명 | 8 | **0.502** |
| 샘플 4개 | 40명 | 98 | **0.610** ±0.188 — fold별 `0.297~0.864` |
| 위를 **20회 반복** | 40명 | 98 | **0.528** — 0.5 와 구분 안 됨 |

| **LifeSnaps** (다른 데이터) | **63명** | **65** | **0.479 ~ 0.540** — 감정 라벨 직접 사용 |

**0.610 은 fold 운이었습니다.** 참가자를 바꿔가며 20회 반복하니 평균 0.528, 95% 구간이 `0.476 ~ 0.579` 로 0.5 를 포함합니다.

**원인은 모델이 아니라 데이터입니다.** 참가자 40명이면 fold 하나에 8명, 그중 양성이 3~4명이라 **한 사람이 지표를 좌우합니다.**

>
> 그래서 참가자가 더 많고 **감정 라벨이 직접 붙어 있는** LifeSnaps 로 다시
> 재봤습니다. 63명 · 피처 65개 · 참가자 단위 분할 20회 반복 — **0.479~0.540** 입니다.
> 정작 잡아야 할 `SAD` 가 0.485, `TENSE/ANXIOUS` 가 0.497 입니다.
>
> 참가자를 늘려도, 피처를 넓혀도, 감정 라벨을 직접 써도 같습니다.
> **전체 데이터(497명)를 기다리는 것으로는 풀리지 않습니다.**
> 재현 스크립트는 [`eval_lifesnaps.py`](eval_lifesnaps.py) 입니다.

받는 방법과 실측 근거는 [`../README.md`](../README.md) 「샘플로 어디까지 되는지」 절에 있습니다.


## 설계에서 짚어둔 것

### 참가자 단위로 나눕니다 (`GroupKFold`)

무작위로 행을 나누면 **같은 사람의 다른 날짜가 학습·평가 양쪽에 들어갑니다.** 14일 히스토리 피처라 연속된 날짜끼리 값이 거의 같고, 그러면 **성능이 크게 부풀려집니다.**

> 이걸 안 하면 지금 샘플에서도 AUC 가 0.9 넘게 나옵니다. 그 숫자를 믿고 진행하면 전체 데이터에서 무너집니다.

### 피처명을 줄입니다

GLOBEM 원본은 `f_slp:fitbit_sleep_summary_rapids_sumdurationasleepmain:14dhist` 처럼 길고 `:` 가 들어 있습니다. **LightGBM 은 피처명에 JSON 특수문자를 허용하지 않아** 그대로 넣으면 `LightGBMError` 로 죽습니다.

이름을 바꾸므로 **저장된 모델의 `features` 순서가 곧 계약**입니다. 추론할 때 같은 순서로 넣어야 합니다.

### 라벨

- `dep` — 이진(우울 여부). 지금 학습에 쓰는 것
- `BDI2` — BDI-II 원점수. 회귀로 갈 때를 위해 남겨둠
